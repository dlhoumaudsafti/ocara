# Fiabilité mémoire du runtime bas niveau — représentation `mixed`, strings, conteneurs imbriqués

## ✅ Historique — fiche reconstituée (fichier perdu, jamais réellement supprimé du code)

Ce fichier avait disparu de `docs/roadmap.d/` (probablement supprimé par erreur lors de la clôture d'un chantier) alors qu'il est encore cité par plus de 20 commentaires directement dans le code source (`runtime/src/lib.rs`, `runtime/src/mutex.rs`, `runtime/src/typecheck.rs`, `src/lower/expr.d/helpers.rs`, `src/lower/expr.d/lower.rs`, `src/lower/stmt.d/ownership.rs`, `src/lower/stmt.d/statements.d/helpers.rs`, `src/codegen/emit.d/emitter.rs`) ainsi que par plusieurs tests de régression (`examples/tests/34_string_nul_safetyTest.oc`, `37_mixed_large_intTest.oc`, `38_mixed_call_arg_boxingTest.oc`, `41_nested_container_ownershipTest.oc`) et par `docs/roadmap.d/packaging-windows.md`. Reconstituée ici à partir de ces commentaires pour que ces références redeviennent valides — **sans elle, un lecteur qui suit un renvoi de commentaire tombe sur un lien mort**, ce qui nuit à la confiance dans la piste d'audit du projet.

Regroupe tous les correctifs déjà faits (confirmés par reproduction avant correction) sur la représentation runtime des valeurs dynamiques (`mixed`) et des strings — racine commune : `runtime/src/typecheck.rs` encode toute valeur dynamique sur un seul `i64`, avec les 2 bits bas comme tag (pointeur / float boxé / bool boxé / int boxé) et un seuil `PTR_THRESHOLD = 65536` pour décider si un entier brut est assez grand pour être confondu avec un pointeur heap.

## Correctifs regroupés ici

1. **NUL-byte interne dans une string** — `alloc_str`/`ptr_to_str` (`runtime/src/lib.rs:157`/`:212`) retrouvaient la longueur d'une string en cherchant le premier octet NUL depuis le pointeur (`CStr::from_ptr`), alors qu'une string Ocara peut légitimement contenir un `\0` en son milieu (`"a\0b"`, échappement valide). Une telle string aurait été tronquée à l'affichage/comparaison, et sa libération aurait utilisé une longueur recalculée plus courte que l'allocation réelle → `Layout` faux passé à `dealloc`, risque de heap corruption. Corrigé en préfixant chaque string (littérale ou allouée) d'un header `[len: i64][tag: i64]` — la longueur réelle est toujours lue, jamais recalculée par scan. Test dédié : `examples/tests/34_string_nul_safetyTest.oc`.
2. **`TAG_STRING_OWNED` séparé de `TAG_STRING`** (`runtime/src/typecheck.rs:31`) — distingue un littéral (`.rodata`, jamais libérable) d'une allocation tas réelle. Avant ce tag, libérer une `scoped string` plantait (`munmap_chunk(): invalid pointer`) dès qu'elle contenait un littéral.
3. **`TAG_EXCEPTION` séparé de `TAG_MAP`** (`runtime/src/typecheck.rs:41`) — un objet exception partageait par erreur le même tag numérique qu'une `map`, ce qui faisait passer `e is map<string, mixed>` pour vrai sur n'importe quelle exception (confirmé par reproduction sur `ArrayException`).
4. **Ambiguïté `0`/`null` et arithmétique/comparaison `mixed`** — `box_int_if_needed` ne boxait aucun petit entier (y compris `0`), rendant `0` indiscernable d'un pointeur nul, et une comparaison `mixed` (`n equal 1000000`) pouvait lire un `i64` brut assez grand pour ressembler à un pointeur heap (`__cmp_eq_strict`/`get_value_type`). Corrigé en boxant systématiquement `0` et tout entier `≥ PTR_THRESHOLD` logé dans un `mixed`, et en passant les deux opérandes d'une comparaison par `box_for_dyn_arith` avant tout dispatch typé au runtime (`src/lower/expr.d/lower.rs:1095` et suivants). Voir aussi `docs/roadmap.d/langage-array-get-display-bug.md` pour le détail de la découverte.
5. **`is ClassName`/`is float` sur un opérande à type statique primitif** — `n is Shape` avec `n:int` déréférençait à tort `read_tag(n)` (SEGFAULT confirmé sur un entier assez grand pour ressembler à un pointeur). Corrigé par un court-circuit statique dans `Expr::IsCheck` (`src/lower/expr.d/lower.rs:1700` et suivants) : un opérande dont le type est connu I64/F64/Bool à la compilation ne passe jamais par le check runtime.
6. **Conteneurs imbriqués (`array<array<T>>`, profondeur arbitraire)** — le chemin `_shallow` protégeait un seul niveau d'imbrication ; au-delà, `__value_free`/`__value_clone` retombait sur le même bug qu'il corrigeait déjà, un cran plus profond. Corrigé par `concrete_elem_shape`/`is_concrete_primitive_elem` (`src/lower/stmt.d/ownership.rs:173`/`:152`), qui calcule la forme des éléments à la compilation (jamais de dispatch par tag runtime sur un primitif brut, à aucun niveau) et pilote les variantes `_concrete` de `free`/`clone`. Test dédié : `examples/tests/41_nested_container_ownershipTest.oc`.
7. **Boxing des arguments d'appel jamais fait pour un appel statique** — un `float`/`bool` passé où le paramètre est `mixed`, ou un décalage d'index sucre/statique (voir `docs/roadmap.d/langage-array-get-display-bug.md`), pouvaient corrompre silencieusement la valeur reçue. Corrigé par `box_arg_for_mixed_param`/`param_type_for_sugar_call_arg` (`src/lower/expr.d/helpers.rs:127`/`:105`). Test dédié : `examples/tests/38_mixed_call_arg_boxingTest.oc`.
8. **`pthread_mutex_t` via `libc` plutôt qu'un tableau d'octets hardcodé par plateforme** (`runtime/src/mutex.rs`) — un `[u8;40]`/`[u8;64]` suffisant sur la glibc testée mais pas garanti sur toute libc aurait laissé `pthread_mutex_init` écrire hors des bornes de l'allocation. Corrigé en utilisant directement le type `libc::pthread_mutex_t`.

## Ce que ce chantier N'a PAS éliminé

Chacun des huit points ci-dessus est un correctif ponctuel trouvé par reproduction d'un bug concret, pas une refonte de la représentation elle-même : la distinction pointeur/valeur reste une heuristique sur la magnitude et l'alignement d'un `i64` (`PTR_THRESHOLD`), pas un tag structurellement sûr. Le risque qu'une neuvième combinaison non encore rencontrée reproduise la même famille de bug reste réel — voir le chantier de suite [memoire-boxing-durcissement](memoire-boxing-durcissement.md), qui traite ce risque résiduel comme un sujet à part entière plutôt que d'attendre une dixième reproduction.
